# Recruitment page
![Recruitment page](/img/using_the_app/recruitment1.png)
![Recruitment page](/img/using_the_app/recruitment2.png)
This page offers a tool to coordinate the recruitment process. Since this is often a long process involving several recruiters and necessitating to contact a lot of people, it can be difficult to keep track of who has been contacted, by whom, and who needs to be followed up on. This tool offers a way to facilitate this process. The users can add names to the list, either manually, by importing them from the database or from another project participant list. The names in the list have several important fields:
- Contact information: even when entering a name manually, at least one way of contact (email, phone or Messenger handle) is needed. While entering the information, the application automatically searches the existing contacts database to detect possible duplicates or similar contacts based on the name, email address or phone number. Existing contacts can then be reused directly to avoid duplicate entries.
- Section (optional): the section in which the person would play. This is purely informative, and has no bearing on the section in which the player is registered when they do.
- Status: this is one of the two key features of the recruitment tool. A person can have several different statuses: not yet contacted, awaiting response, follow-up, not available, recruited, cancelled or pending validation. Additional custom statuses can also be created using the "+ statuses" button and are saved permanently for the project. The tool has a feature to automatically pass all the people who have been on "awaiting response" for more than a set amount of days to "follow up".
- Contacted by: this is the second key feature, and lets all the active recruiters see who is "assigned" to contacting a specific person. It lets recruiters avoid contacting the same person twice. By default, whenever a name is added to the list, this field takes the name of the user that is logged in. 
- Source: this gives the source of the person. It can be database import if the name has been imported from the database, manually added if the name has been added manually, database_auto_import if the person has been added automatically when registering (which happens if a person registers but was not in the list, to make sure that person is not contacted again), or recommendation, if the person is added from a recommendation (see below)
- Actions: this section contains buttons to call the person (if using the app on a smartphone), send an email, edit the status or any other field, or delete the person from the list.
This page has a powerful filtering engine to allow users to only show names that satisfy one or more criteria (e.g. a recruiter wants to see only people assigned to him/her, and that have a status not yet contacted or follow up).  
This page also has a recommendations tab:
![Recommendations page](/img/using_the_app/recruitment3.png)
Here are displayed all the people that have been recommended by someone through a recruitment mail (automated recruitment emails offer the possibility to recommend someone else). From this page, the user can see the recommended names (the recommendations tool also collects at least a way of contacting them), and can decide whether to follow up on the recommendation and send the person a recruitment email as well, or not. If they do, the person is added to the recruitment list.  
The last tabs shows statistics about the recruitment process. They are purely informative, but allow to collect meaningful data on recruitment strategies over several projects, to see if one is more efficient than the other
