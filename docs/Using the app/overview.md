# Overview

## General logic
### Contacts and participants
The app is centered around a contact manager. It is actually a very overpowered phonebook. The database contains contacts, and stores a very specific set of data useful to orchestras (basic personnal data, instruments played and corresponding levels, projects played, some comments,...). Next to that, the database contains projects, which correspond to productions by the orchestra. One project is linked to a bunch of events, which can be rehearsals or concerts. In order for a contact to participate in a project, they have to register through a registration form specific to the project, where they have to indicate their presence and absence to all rehearsals and concerts (in order to make an attendance tabel), and their personal data. This is then used to compare to the database, and find a match (or not). When the user then goes to accept (or not) the registration, they have to link it to an existing contact or create a new one. This ensures that all participants are always in the database. A participant is a separate type of data linking a contact to a project. A contact can of course participate in multiple projects, and for every project, the app needs to store attendance and other data specific to that project, so it would not be practical to reference contacts directly in a project. 

### Information management
One of the main strengths of this app is the information management, which is a big part of managing an orchestra project. The app offers two ways of spreading informations about a project to its participants:
- **Mailing:** The app supports mailing, to one, multiple or all participants of a project, and even does it automatically sometimes, like at registration. The app automates the mailing, and offers easy options to send templates with personnalized fields (name, project,...). This feature is not intended to distribute all the informations of a project, but merely as a notification system. The participants get a confirmation notification when their registration is confirmed, containing the link to the callsheet (see below), and then they may get a few emails to notify them of changes to the project info, or urgent requests. 
- **Callsheets:** These are static pages, always accessible, containing all project infos. They are created by default with a project with already all the basic infos the app has about the project (calendar, pieces, project managers,...) and are then completed by the user with all the other informations specific to that project (adresses, names of soloists/conductors,...). This page is mailed to every participant at registration, and a notification can be mailed to every participant when it is updated.

### Pieces, composers, materials
Next to that, the database also contains some trivia. When the user creates a project, they have to indicate the program, and the pieces need to be in the database. For every piece, the database contains some basic data (date composed, opus number,...) and a link to a composer (for which the database also stores some trivia: nationality, birth and death, ...), the projects it has been played in and possibly one or more materials, which are sets of pdfs containing the scores. When creating a project, the user will be asked to select an existing material for every piece or upload a new one, so that the scores can be downloaded by the participants from the callsheet. A piece can have several materials, since depending on the conductor and concertmaster, the annotations in it might be different.

### Other features
We listed the core features of the app, but it has multiple other management features built in to facilitate project management (more details will be given on the next page, since this is only an overview):
- **Auditions management:** If a musician fills the registration and needs to be auditioned, the app has a built-in auditions manager, allowing the user to send an audition request to the candidate, containing an audition package (pdfs with the excerpts, and text instructions with the precise instructions) and a link to a personnal portal where they can upload their audition. They can keep coming back to it, uploading new excerpts (no need to upload everything at once), and once they are done, they can confirm, closing the portal for them. Once they are done, the audition videos appear on the user side, and need to be reviewed. The user can then approve or deny the registration of the candidate.
- **Accounting:** Every project has a dedicated accounting page, allowing the user to add incomes and expenses, upload files for every transaction, divide them into categories,... The page then displays a dashboard with a few key data points, making a distinction between future and past transactions, allowing to see not only the total balance of the project, but also the current balance. Since a lot of the transactions are payments to musicians, the app records them as a separate category, and shows those payments in the participants list of the project, as wel as on the contacts page of the relevant people. If some contacts participate and are paid in multiple project, the app shows what the orchestra currently owes them.
- **Recruitment:** A big part of organizing a project is finding the people for the orchestra. Since most of the time, this is done by several people, to avoid contacting the same people multiple times and to help keep track of who needs to be followed up on and so on, the app has a dedicated page to make a list of the people that were contacted. It stores the name, some way of contacting them and their instrument, as well as the person who contacted them and their status (not contacted yet, awaiting response, confirmed,...). This page has some intelligent features to facilitate the process, such as marking automatically everyone that has been on "awaiting response" for more than a fixed delay as "follow up", automatically changing the status to "confirmed" when people register to the project (or adding them to the list as confirmed is they are not in it yet), advanced filtering to only show some instruments, categories, etc. 
- **File management:** The app has a drive, where it can organize files, and associate folders to a project in order to make them available on its callsheet. This is a way to share pictures, posters or recordings with the orchestra without having to use external services, for instance. but files can also be stored seperately from projects, removing the need for expensive subscriptions to the cloud.
